# 👑 پادشاه انتخاب‌ها (Kingdom of Choices)

بازی استراتژی، شبیه‌سازی و تصمیم‌گیری پادشاهی — فارسی، راست‌به‌چپ، آفلاین‌اول، داده‌محور و قابل‌گسترش.

> شما فرمانروا هستید. هر انتخاب حداقل یک مزیت و یک هزینه یا ریسک دارد و روی اقتصاد، مردم، ارتش، دیپلماسی و قلمرو اثر زنجیره‌ای می‌گذارد.

## 🎮 تجربه بازی

- **ساخت فرمانروا**: نام، لقب، نماد، پرچم، رنگ و یکی از ۵ سبک حکومت (جنگجو، بازرگان، محبوب، استراتژیست، توسعه‌طلب)
- **دربار تصمیم‌گیری**: هر روز یک رویداد (بیش از ۳۶ رویداد با انتخاب‌های چندهزینه‌ای، ریسک تصادفی و زنجیره‌های داستانی)
- **اقتصاد زنده**: مالیات ۵ سطحی، رفاه، بودجه امنیت/ارتش/کشاورزی/علم، بازار با قیمت‌های پویا
- **ساختمان‌ها**: ۱۵ ساختمان چندسطحی (مزرعه، بازار، دیوار، قلعه، دانشگاه، بندر…)
- **ارتش و جنگ**: ۵ واحد، آموزش، روحیه، ۵ ژنرال با ویژگی‌های متفاوت، نبرد محاسباتی با گزارش کامل
- **دیپلماسی**: ۵ کشور همسایه؛ هدیه، پیمان تجاری، اتحاد، تهدید، جاسوسی، اعلان جنگ و صلح
- **نقشه قلمرو**: ۶۳ کاشی؛ گشایش مناطق آزاد و فتح خاک همسایه‌ها
- **فناوری**: درخت ۱۴ فناوری‌ای در ۷ شاخه
- **پیشرفت**: مأموریت‌های روزانه/هفتگی/داستانی، ۱۴ دستاورد، ۱۲ لقب، سطح و XP
- **پایان‌های چندگانه**: امپراتوری طلایی، شورش، فتح، فروپاشی اقتصادی، قحطی + حالت New Game+
- **تاریخ سلطنت**: آمار کامل + خط زمان وقایع

## 🚀 اجرا (وب)

```bash
npm install        # فقط برای ابزارها (Capacitor/http-server)
npm start          # http://localhost:8080
```

بازی کاملاً **آفلاین** است؛ با اولین بازدید، Service Worker همه دارایی‌ها را کش می‌کند و به‌عنوان **PWA قابل نصب** است.

## 📱 دریافت APK اندروید

هر بار که روی شاخه `main` پوش می‌شود، **GitHub Actions** به‌صورت خودکار:

1. پلتفرم اندروید را با Capacitor می‌سازد (`cap add android` + `cap sync`)
2. فایل `APK` را با گریدل بیلد می‌کند
3. آن را در بخش **Releases** با تگ `apk-latest` و نیز به‌عنوان Artifact آپلود می‌کند

📥 دانلود: **Releases → «آخرین نسخه (APK)» → kingdom-of-choices.apk**

بیلد محلی:

```bash
npm run cap:android          # یک‌بار: ساخت پروژه اندروید
cd android && ./gradlew assembleDebug
```

## 🏗 معماری (بند ۵۱ سند طراحی)

```
www/
├── core/           ← موتور بازی (بدون وابستگی به محتوا و UI)
│   ├── gameEngine.js         ارکستراتور چرخه روزها و API عمومی
│   ├── decisionEngine.js     انتخاب رویداد، اعمال انتخاب، پرچم و زنجیره
│   ├── economyEngine.js      تولید/مصرف، مالیات، جمعیت، بازار
│   ├── warEngine.js          فرمول نبرد و گزارش
│   ├── diplomacyEngine.js    رابطه‌ها و اکشن‌های دیپلماتیک
│   ├── progressionEngine.js  XP/سطح، مأموریت، دستاورد، لقب
│   ├── conditionEngine.js    موتور شرط (AND/OR/NOT، داده‌محور)
│   ├── effectEngine.js       موتور اثر (رجیستری پلاگین‌مانند)
│   ├── saveManager.js        ذخیره نسخه‌بندی‌شده + مایگریشن + پشتیبان
│   ├── contentManager.js     رجیستری محتوا با قابلیت فعال/غیرفعال
│   ├── eventBus.js / rng.js
├── content/        ← داده‌های بازی (جدا از هسته؛ بدون تغییر هسته گسترش می‌یابند)
│   ├── events / buildings / units / generals / countries
│   ├── missions / achievements / technologies / titles / mapTiles / royalStyles
├── ui/             ← صفحات و کامپوننت‌ها (فقط از API عمومی موتور استفاده می‌کنند)
├── services/       ← storage / sound / notification / analytics / api
├── config/         ← gameConfig.js (تمام بالانس) + localization
├── admin.html      ← پنل مدیریت محلی (فعال‌سازی/غیرفعال‌سازی، بالانس، فیچر فلگ)
├── sw.js           ← Service Worker آفلاین
```

**اصل طلایی:** هسته هیچ آیتم محتوایی را نمی‌شناسد؛ همه‌چیز با **ID یکتا** (`event_famine_001`, `building_farm_001`, …) و از رجیستری محتوا خوانده می‌شود.

## ⚙️ بالانس و پیکربندی

تمام اعداد از `www/config/gameConfig.js` می‌آیند (منابع شروع، مالیات، منحنی XP، وزن رویدادها، فرمول جنگ، بازار…).
از **پنل مدیریت** (`/admin.html` یا لینک در تنظیمات) می‌توان بدون دست‌زدن به کد:

- هر رویداد/ساختمان/واحد/کشور/مأموریت را فعال یا غیرفعال کرد
- بالانس را با JSON override تغییر داد (مثلاً `{"start":{"coins":1000}}`)
- فیچر فلگ‌ها را روشن/خاموش کرد (`feature.market`, `feature.war`, …)

در نسخه آنلاین، همین ساختار به Remote Config سرور متصل می‌شود.

## 💾 ذخیره و مایگریشن

- ذخیره خودکار پس از هر روز + ذخیره دستی
- `saveVersion` و زنجیره مایگریشن (در حال حاضر نسخه ۲؛ مایگریشن ۱→۲ موجود)
- ۳ پشتیبان چرخشی؛ در صورت خرابی ذخیره اصلی، بازیابی خودکار از پشتیبان
- خروجی/ورودی ذخیره برای انتقال بین دستگاه‌ها
